# 주말 신청 점검 웹앱 설치 안내

처음 한 번만 하면 됩니다. 약 40분 걸립니다. 순서대로 따라 해 주세요.

준비물: 구글 계정, GitHub 계정, NEIS 인증키, 이 저장소의 파일들

전체 구조는 이렇습니다.

```
[웹 화면: GitHub Pages]  →  [저장·점검: Apps Script]  →  [구글 시트]
   폴더에서 명단 읽기            로그인 확인·점검 규칙          데이터 보관
```

---

## 1단계. 구글 시트와 Apps Script

1. 구글 드라이브에서 **새 구글 시트**를 만들고 이름을 `주말 신청 점검`으로 정합니다.
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 왼쪽 **⚙ 프로젝트 설정**에서 **"편집기에서 'appsscript.json' 매니페스트 파일 표시"**를 체크합니다.
4. 왼쪽 **< > 편집기**로 돌아와 파일 3개를 채웁니다.
   - `Code.gs`: 원래 있던 내용을 지우고 `gas/Code.gs` 내용을 붙여넣습니다.
   - `+` → **스크립트** → 이름을 `Core`로 하고, `gas/Core.gs` 내용을 붙여넣습니다.
   - `appsscript.json`: 내용을 지우고 `gas/appsscript.json` 내용을 붙여넣습니다.
   - 💾 저장을 누릅니다.
5. 위쪽 함수 선택 칸에서 **`setupSheets`**를 고르고 **▶ 실행**을 누릅니다.
   - 권한 창이 뜨면 **권한 검토 → 계정 선택 → 고급 → (안전하지 않음)으로 이동 → 허용**을 누릅니다. 직접 만든 스크립트라서 나오는 경고입니다.
6. 시트로 돌아가면 탭이 여러 개 생겨 있습니다. 아래 탭을 확인합니다.
   - **설정_수업일**: 하반기 10회차 날짜가 맞는지 확인합니다. 6~10회차(11/7~12/5)는 예상값으로 넣어 두었습니다.
   - **설정_반**: 하반기 반 구성입니다. 창의반은 키워드를 비워 두어서 첫 업로드 때 어느 반인지 묻습니다.
   - **점검자**: 함께 점검할 선생님의 **구글 이메일과 이름**을 한 줄씩 추가합니다. 여기 없는 계정은 로그인이 안 됩니다.
7. Apps Script **⚙ 프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**
   - `NEIS_KEY` = 발급받은 NEIS 인증키
   - (`CLIENT_ID`는 2단계에서 넣습니다)
8. 시트를 새로고침하면 메뉴에 **주말 점검**이 생깁니다. **주말 점검 → NEIS 학교 목록 가져오기**를 누르면 `설정_학교` 탭이 채워집니다.
9. Apps Script 오른쪽 위 **배포 → 새 배포**
   - 유형 선택(⚙) → **웹 앱**
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - **배포**를 누르고, 나오는 **웹 앱 URL**(`…/exec`로 끝남)을 복사해 둡니다.

> "모든 사용자"로 열어도 안전합니다. 요청마다 구글 로그인을 확인하고, **점검자 탭에 있는 계정만** 명단을 볼 수 있습니다.

## 2단계. 구글 로그인 설정 (구글 클라우드)

1. https://console.cloud.google.com 에 접속해 위쪽 프로젝트 선택 → **새 프로젝트** → 이름 `weekend-checker` → 만들기.
2. 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**(또는 "Google 인증 플랫폼") → **시작하기**
   - 앱 이름 `주말 신청 점검`, 지원 이메일 선택 → 대상 **외부** → 연락처 이메일 → 만들기.
3. **대상(Audience) → 테스트 사용자 → 사용자 추가**에 점검자 이메일을 모두 넣습니다. 테스트 사용자만 로그인할 수 있어서 더 안전합니다.
4. **클라이언트 → 클라이언트 만들기**
   - 애플리케이션 유형: **웹 애플리케이션**
   - **승인된 JavaScript 원본**: `https://내GitHub아이디.github.io`. 끝에 `/`나 저장소 이름은 붙이지 않습니다.
   - 만들기 → **클라이언트 ID**(`….apps.googleusercontent.com`)를 복사합니다.
5. Apps Script **스크립트 속성**에 `CLIENT_ID` = 복사한 클라이언트 ID를 추가합니다.

## 3단계. GitHub Pages (웹 화면)

1. GitHub에서 **New repository** → 이름 `weekend-checker` → **Public** → Create.
2. **Add file → Upload files**에서 `docs` 폴더 **안의 파일들**을 끌어다 놓습니다.
   - `index.html`, `app.js`, `core.js`, `config.js`, `style.css`, `vendor` 폴더(안에 `xlsx.full.min.js`)
   - **Commit changes**를 누릅니다.
3. 저장소에서 `config.js`를 열고 ✏ 편집을 눌러 두 값을 바꿉니다.
   - `API_URL`: 1단계 9번의 웹 앱 URL
   - `CLIENT_ID`: 2단계 4번의 클라이언트 ID
   - **Commit changes**를 누릅니다.
4. **Settings → Pages → Branch: main / (root) → Save**. 1~2분 뒤 주소가 나옵니다.
   `https://내아이디.github.io/weekend-checker/`
5. GitHub 계정에 **2단계 인증**을 꼭 켜 주세요. 이 계정만 화면 코드를 고칠 수 있습니다.

## 4단계. 처음 사용

1. 크롬이나 엣지에서 위 주소를 열고 **즐겨찾기**에 추가합니다.
2. **구글 계정으로 로그인**합니다(점검자 탭에 등록된 계정).
3. 홈에서 **폴더 변경 → 다운로드 폴더 선택**을 합니다. "파일 보기 허용" 창이 뜨면 허용하고, 가능하면 **"방문할 때마다 허용"**을 고릅니다.
   - ⚠️ **"파일 수정/저장 허용" 창은 절대 허용하지 마세요.** 이 웹앱은 읽기만 합니다.
4. 통합예약시스템에서 반별 엑셀을 내려받은 뒤 **명단 올리기**를 누릅니다.
   - 접수 기간(수업일 6일 전 ~ 수업일)에 받은 `통합예약신청자목록 - ….xls` 파일만 올라갑니다.
   - 처음 보는 예약명(창의반 등)은 어느 반인지 물어봅니다. 한 번 고르면 기억합니다.

## 업데이트할 때

- **Apps Script**: 코드를 바꿔 붙여넣고 저장 → **배포 → 배포 관리 → ✏ → 버전: 새 버전 → 배포**. 주소는 그대로 유지됩니다. "새 배포"를 누르면 주소가 바뀌니 주의하세요.
- **웹 화면**: GitHub에서 바뀐 파일만 다시 올리면 1~2분 뒤 반영됩니다.
- `gas/Core.gs`와 `docs/core.js`는 **같은 내용**이어야 합니다. 둘 중 하나만 고치면 판정이 달라집니다.

## 자주 묻는 문제

| 증상 | 해결 |
|---|---|
| 로그인 후 "점검자로 등록되어 있지 않습니다" | 시트의 **점검자** 탭에 그 이메일을 추가 |
| 로그인 버튼이 안 보이거나 오류 | 2단계 4번의 **JavaScript 원본** 주소가 GitHub 주소와 정확히 같은지 확인 |
| "스크립트 속성 CLIENT_ID가 없습니다" | 2단계 5번 확인 |
| 명단 올리기 후 "연결 필요" 창 | 그 예약명이 어느 반인지 고르면 다음부터 자동 |
| 화면 내용이 옛날 그대로 | 다른 선생님 작업은 20초 안에 반영됩니다. 급하면 새로고침(F5) |
| 학교가 관외로 잘못 나옴 | `설정_학교` 탭에 학교를 추가합니다. 학교급 칸에 `직접`이라고 쓰면 NEIS로 새로 가져올 때 지워지지 않습니다 |

## 개인정보 관리

- 구글 시트는 **점검하는 선생님에게만** 공유하세요. 웹앱은 시트를 공유받지 않아도 사용할 수 있습니다.
- 학기가 끝나면 `통합명단`, `처리기록`, `업로드기록` 탭의 내용을 지워 주세요.
